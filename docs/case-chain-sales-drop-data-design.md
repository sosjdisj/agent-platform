# 案例链数据设计：客户 A 销售额下降分析（Prompt 4.1）

> 用途：为「客户智能分析 Agent」提供一条端到端可评估的真实业务案例链，覆盖 DataAgent（订单/销售数据）、KnowledgeAgent（企业制度/产品资料，另建）、BusinessAgent（客户工单）三类数据源，供 Evaluation 体系作为标准评估用例。

## 1. 设计原则

1. **可推理、不自曝答案**：所有表中**不设计任何归因类字段**（不新增任何描述"下降原因/问题原因"的列）。销售额下降的结论只能通过 **订单时序 + 投诉文本现象** 交叉推理得出，任何单表都无法直接读出答案。
2. **对照组控制变量**：设计正常客户 B（同行业、同区域、同核心产品、同期）。B 的订单平稳、无交付类投诉，用于排除"产品问题、市场大盘问题、季节性因素"，将结论收敛到客户 A 特有的**供货交付问题**。
3. **仅使用现有表结构**：`customers` / `products` / `orders` / `sales_records` / `customer_tickets`，遵守逻辑外键约定（应用层保证引用完整性），不新增迁移。
4. **时间基准**：以 2026-09-19 为评估时点。"近 3 个月"取最近 3 个完整自然月：**2026-06 / 07 / 08**；基准期取 **2026-03 / 04 / 05**（体现"从正常水平逐月下降"）。
5. **口径说明**：`orders` 为逐单记录（每客户每产品每月 1 单，便于核对）；`sales_records` 为月度汇总（每客户每产品每月 1 行，金额 = 当月该产品订单合计），两表数值严格一致。

## 2. 案例总览（推理链）

```
                    ┌──────────────────────────────────────────────┐
 下降组（客户 A）     │  orders: 核心产品 P1 月订单量 500→520→480→300→180→120 │
                    │  tickets: 3 条投诉＝部分到货延迟 / 连续两月缺货 / 供货稳定性质疑 │
                    └──────────────┬───────────────────────────────┘
                                   ▼
              可推理结论：P1 供货不稳定（缺货、延迟交付）→ 客户 A 削减 P1 采购
                    ▲
                    │ 对照后排除：产品 / 市场 / 季节性因素
                    ┌──────────────┴───────────────────────────────┐
 对照组（客户 B）     │  orders: 同期 P1 月订单量 470→500→480→510→490→520（平稳）│
                    │  tickets: 仅 2 条日常工单（发票更正 / 产品咨询），无交付类投诉 │
                    └──────────────────────────────────────────────┘
```

关键设计点：

- 客户 A 的次要产品 P2 订单**完全平稳** → 排除"客户自身经营恶化"；
- 客户 B 同期 P1 平稳 → 排除"产品缺陷 / 市场下行 / 季节性"；
- 客户 A 投诉仅描述**现象**（缺货数量、延迟天数、产线受影响），不写任何归因语句 → 答案需由 Agent 关联订单下降与投诉内容后自行归纳。

## 5. 预期推理路径（评审用，非数据内容）

评审人应确认：Agent 在只读上述数据的情况下，能够完成以下推理链，且每一步都有数据支撑、无一步是数据直接"告知"的：

1. **发现异常**：聚合 A 的销售额，发现近 3 个月（6/7/8）逐月下降，8 月较基准期月均下降约 76%；
2. **定位范围**：下钻产品维度 → 仅 P1 下降，P2 平稳 → 排除客户整体经营恶化；
3. **对照分析**：对比客户 B 同期 P1 平稳 → 排除产品本身、市场大盘与季节性因素；
4. **归因关联**：检索 A 的工单 → 3 条投诉均指向 P1 缺货 / 延迟交付，且首次投诉时间与订单骤降同月 → 归纳"我方对 P1 的供货交付不稳定，导致客户削减采购"；
5. **报告产出**：给出风险提示（T-2608-002 未解决，存在转向其他采购渠道的流失风险）与建议。

## 6. 可选扩展（不在本期实施）

若后续需要结构化供货证据，可增加月度库存快照表（产品 × 月份的可用库存量），使 6–8 月 P1 可用量明显低于基准期。本期案例链**不依赖**该表，归因完全由订单 + 工单完成，故暂不新增。
